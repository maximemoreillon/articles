# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A personal Hugo static site (blog) published to `https://articles.maximemoreillon.com/`. Content is a flat
collection of Markdown articles; the active theme and site-specific behavior (search overlay, dark/light
toggle) are layered on top via `layouts/` overrides and `assets/sass/_custom.scss`.

## Commands

```
hugo server              # local dev server with live reload
hugo                     # production build, outputs to ./public
npx -y pagefind --site public   # build the client-side search index (run after `hugo`)
```

Theme code lives in `themes/*` as git submodules and is not checked out by a plain clone:

```
git submodule update --init --recursive
```

There is no test suite or linter in this repo.

## Deployment

`.github/workflows/deploy.yml` runs on every push to `master`: checks out submodules, builds with Hugo
`0.147.8` (extended), indexes the build with Pagefind, then publishes `./public` to GitHub Pages
(custom domain `articles.maximemoreillon.com` via the `cname` input). There is no separate staging step —
pushing to `master` deploys.

## Site configuration

`hugo.toml` sets `theme = 'hugo-blog-awesome'` — this is the only theme actually in use. `Params.author`,
the favicon, and the `main` menu (Home / Articles / Tags) are configured here.

## Themes directory

`themes/` contains several git submodules (`ananke`, `congo`, `hello-friend-ng`, `hugo-coder`,
`hugo-blog-awesome`), each pointing at an upstream theme repo per `.gitmodules`. Only `hugo-blog-awesome` is
selected in `hugo.toml`; the others are present from past experimentation and are not wired up.

`themes/moreillon` is **not** a submodule — it's a plain directory checked directly into this repo (a
theme skeleton/example with its own `hugo.toml`, `archetypes/`, and sample `content/posts/*`). It is not
referenced by the site's `theme` setting and is not part of the build.

## Overriding the active theme

Site-specific behavior is layered on top of `hugo-blog-awesome` via Hugo's standard override mechanism
(same relative path under the project root takes precedence over the theme):

- `layouts/partials/header.html` overrides the theme's header partial to add the Pagefind search overlay
  (`#search-overlay`, `Ctrl+K` shortcut) and the light/dark mode toggle, in addition to the main nav.
- `assets/sass/_custom.scss` adds/overrides styles on top of the theme's Sass, including the Pagefind UI
  theme variables (mapped to the theme's own `$text-link-blue`, `$dark-*` variables, etc.) and the search
  overlay's look.

When changing header behavior or search UI, check both files together since the JS wiring in
`header.html` and the styling in `_custom.scss` are coupled (element IDs like `#search-overlay`,
`#search-trigger`, `#search-box` must match between them).

## Content

- All articles live flat under `content/articles/*.md`. Filenames are a mix of legacy short numeric IDs
  (e.g. `11.md`, `160.md` — carried over from a prior CMS/URL scheme) and newer UUID-based filenames (e.g.
  `03878fe3-1eca-4f22-9521-0589ba076930.md`); the filename becomes the URL slug since no custom
  `permalinks` are set in `hugo.toml`. Don't rename existing article files — it changes their published URL.
- Front matter is YAML (`---` delimited), with `title`, `date`, `lastmod`, `tags`, and `draft` (from the
  archetype) as the common fields. (Site config in `hugo.toml` stays TOML — only article front matter is
  YAML.)
- New articles should be created with `hugo new content articles/<name>.md` so they pick up
  `archetypes/default.md` (sets `date`, `draft = true`, and a title derived from the filename).
- Article bodies are plain Markdown; images are typically referenced by absolute URL (external image host)
  rather than bundled page resources.

## Build artifacts

`public/` (Hugo output) and `resources/` (Hugo's asset cache) are git-ignored and untracked — never hand-edit
or commit into them; they're regenerated by `hugo`/`hugo server`.
